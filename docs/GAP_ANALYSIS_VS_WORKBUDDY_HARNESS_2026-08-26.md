# SUPERCRZY BOT vs WorkBuddy vs DeepSeek Harness — 全面差距体检

> 日期：2026-08-26
> 方法：逐维度对比，判定标准唯一 = **谁在技术 / 体验上更好**，不因"我们有"就算优势。
> 事实来源：SUPERCRZY（本项目全量代码+实测）、WorkBuddy 5.3.14（app.asar 解包实证+深挖文档）、DeepSeek Harness dsh（GitHub README+架构文档）。
> 结论前置：**三者是三种定位，Harness 强在"架构/生态"，WorkBuddy 强在"桌面端成熟体验"，我们强在"Web 轻量 + 特定体验细节"。没有谁全面碾压。**

---

## 〇、一句话定位

| 产品 | 定位 | 目标用户 | 阶段 |
|---|---|---|---|
| **WorkBuddy** | 成熟桌面 AI 助手（Web+桌面），体验打磨到商业级 | 大众生产力用户 | 商业 5.3.14 |
| **DeepSeek Harness** | 开发者级 Agent 运行时框架，一切皆插件 | 开发者/研究者 | 0.1.x 开发者预览 |
| **SUPERCRZY BOT** | 轻量 Web/桌面自部署 Agent，极简交互 | 个人/小团队自用 | 迭代中（未开源） |

**关键认知**：Harness 与 WorkBuddy/我们**不是同赛道**——Harness 更像"Agent 开发框架/运行时"，你要"拿来二次开发"；WorkBuddy 和我们是"直接可用的产品"。所以下面的对比会区分"产品体验"与"架构可扩展性"两条线。

## 一、架构与技术线（谁更先进 / 可扩展）

| 维度 | WorkBuddy | Harness | SUPERCRZY |
|---|---|---|---|
| 进程模型 | Electron 主/渲染 + **Sidecar Agent 引擎**（ACP over HTTP） | 单进程 + 插件树（Cordis），headless/web 双 profile | Koa 常驻后端 + Vue 前端（同源对话） |
| 扩展机制 | 插件市场 / SKILL.md / MCP 连接器 | **一切皆插件**：模型/工具/会话日志/agent-loop 均可替换 | MCP + 技能(Agent Skills 对齐) |
| 事件模型 | 内部流式 + toolCallId 归属 | **事件驱动一等公民**：SessionEvent/turn/step/tool 双事件域 + 溯源不变量 | SSE 事件流 + 前端状态机 |
| 上下文溯源 | Messages 类 + serializeTranscript | **"模型可见即已记录"** 的不变量、会话日志投影出模型历史、可 fork | flow 持久化还原，较粗 |
| 工具流水线 | 流式执行 + 并行 + 部分成功 | **作用域工具注册表 + pre/execute/post 把关流水线** + seam 可换后端 | executeToolCalls + 工具守卫 |
| 生态开放度 | 中（插件市场+技能） | **极高**（每个能力是 seam，可无补丁替换，本地/远程沙箱可搬移） | 低（当前未开源，技能/MCP） |
| 结论 | 架构扎实，但闭源 | **架构最先进**，开发者友好 | 架构够用，扩展性最弱 |

**技术线结论**：**Harness 架构显著领先**（事件溯源、插件树、seam），WorkBuddy 次之（sidecar 分离成熟），我们最"传统"（虽分层清晰但无插件树/事件溯源）。如果你要的是"高级 Agent 平台"，Harness 架构最好；如果你要"开箱即用的产品"，架构不在第一优先级。

## 二、体验线（谁更好用 / 更顺眼）

| 维度 | WorkBuddy | Harness | SUPERCRZY | 谁更好 |
|---|---|---|---|---|
| **对话流式** | 正文/思考/工具全链路流式 | LLM 流式词汇表，流式是核心 | 正文/思考 SSE 流式，工具流式 | 三者都强，平手 |
| **思考展示** | 思考级别映射(off→xhigh)+reasoning 流式+可折叠 | agent 事件驱动，UI 可自定制 | 思考流式+ThinkingBlock+折叠 | WorkBuddy 最完善，Harness 待自建，我们要补级别档 |
| **过程折叠** | **回看式计算折叠**（正文后判 shouldFold）+ 语义摘要 + 分批展开 + 常驻入口 | 无既定折叠（会话日志只管记录）| 状态机折叠 + 即时折叠 + 摘要条（但曾反复伸缩）| **WorkBuddy 最好**（折叠时机/技巧最成熟）；我们次之；Harness 无 |
| **来源/引用** | 来源链接卡片化 + 正文剥离 | 无专门 | 来源卡片 + 正文剥离(近期刚做) | WorkBuddy 成熟,我们刚追上 |
| **多模态** | 图片输入/生成 (ImageGen/VideoGen) | Web 多模态图片输入 | 附件上传(图片),无生成 | WorkBuddy 最强,我们缺生成 |
| **文件/工作区** | FileTabs + diff + 行数统计 | 工作区 + fs seam + LSP | 产物卡片+文件预览+目录 | WorkBuddy 最丰富 |
| **桌面形态** | 商业级 Electron(深链/自动更新/签名路线) | 无桌面,纯 Web/CLI | Web+PWA+Electron(未签名) | **WorkBuddy 全面领先** |
| **极简上手** | 安装器(仍需下载安装) | **要复制 `npx dsh web` 命令** | **双击即起 + 免命令 + 后台保活(刚做)** | **我们上手最顺**(双击即用)；WorkBuddy 次之；Harness 最麻烦 |
| **界面简洁度** | 功能多→信息密度较高 | 开发者向,功能未铺满 | 极简(禁止 emoji/原创设计) | 我们和 Harness 更克制,WorkBuddy 功能全但密 |

**体验线结论**：
- **折叠、过程可视化、桌面、多模态、文件工作区** → **WorkBuddy 全面更好**，尤其折叠逻辑（回看式+分批+摘要是我们一直在追赶的）。
- **一键上手、极简交互** → **我们最好**（双击起+免命令+无 CLI 门槛），这正是你刚让我做的差异化。
- **Harness** → 体验层目前最"裸"，Web UI 是基本盘，深度/精致度不如前两者（它把体验留给你用插件自建）。

## 三、记忆与上下文（谁"记得住、会复用"）

| 维度 | WorkBuddy | Harness | SUPERCRZY | 谁更好 |
|---|---|---|---|---|
| 记忆存储 | agent_memory 类 + memory_store 工具 + 5问反思 | 会话事件日志(可回放),无独立记忆库 | agent_memory + syncTurnMemories + 5问反思(reflection) | WorkBuddy/我们都有反思注入；Harness 靠事件日志 |
| 记忆注入 | buildMemoryLines(教"何时存") + 按需 recall | 靠上下文组装(agent.inject) | 记忆注入 system prompt + rankMemories 相关性过滤 | **WorkBuddy 引导最成熟**；我们次之；Harness 原始 |
| **主动回忆意识** | **Harness/模型会到处查证(用户观察)**；我们无"主动回忆"引导(近期讨论) | 会话可续跑 | 记忆被动注入,少主动 recall | **我们最弱**(正好在补"续跑注日志摘要") |
| 上下文窗口 | 按模型三层(窗口+驱逐+总结) | turn 事件日志投影(完整) | 前端全量发送(近期查:无滑动窗口) | **WorkBuddy 最完善**；Harness 事件溯源原理强；我们最弱(全量发) |
| 任务续跑 | 检查点/会话恢复 | fork + 恢复(事件日志) | 检查点(近期补中断自动落点) | Harness 事件级最稳,WorkBuddy 次之,我们刚起步 |

**记忆结论**：**WorkBuddy 的"记忆引导+窗口管理"最完善**；Harness 靠事件溯源(原理先进但缺开箱引导)；**我们最弱**——目前是"被动注入"为主、上下文全量发送、主动回忆意识缺失。这正是接下来要补的（你已在关注）。

## 六、诚实结论（3 条，不吹）

1. **我们对标的是"轻量自用产品"，不是 Harness（那是框架）**。拿 Harness 比"体验"不公平——它把体验留给开发者自建；但拿它比"架构"，我们落后且不必要追赶（除非要做平台）。

2. **真正该追的是 WorkBuddy 的"产品成熟度"**，逐项优先级：
   - 🔴 记忆：**主动回忆引导 + 上下文滑动窗口**（我们最弱，且直接影响"记得住/懂你"）
   - 🔴 折叠打磨：**提升到 WorkBuddy 回看式/分批/摘要**（我们状态机已成型，差"技巧"）
   - 🟡 多模态：图片生成/更丰富附件
   - 🟡 工作区：文件 tab/diff/行数统计

3. **我们已建立的两个真实差异点要保住**：
   - 🥇 **一键启动 + 免命令 + 后台守护不挂**（WorkBuddy 要装包、Harness 要 CLI，我们双击即用）
   - 🥇 **极简原创交互**（无 emoji、轻量、体验干净）
