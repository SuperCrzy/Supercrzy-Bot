## 0. 一句话定位

> 用户只给"想法 + 最终验收"，中间由"执行 AI → 质检 AI → 议院"分层把关，
> 以"半自动(你主导) / 全自动(AI 自治) / 自动联动升议院"三档强度，
> 自动完成、自动纠错、多源对证，交付"最完美结果"。

## 1. 功能清单

### 1.1 核心功能
| 功能 | 说明 |
|---|---|
| **任务发布** | 侧边栏"超级任务"分类组置顶；发布时选强度档位 |
| **多 AI 协作对话流** | 执行/质检/议院各自身份，头像=对应品牌 LOGO（DeepSeek/Kimi/GPT…）|
| **执行阶段** | 任一模型(带工具)真正执行任务，产出交付物 |
| **质检阶段** | 质检 AI 多维审(功能/逻辑/事实/格式/边界) + 带证据问题 |
| **议院模式** | 多品牌 AI 各自独立审+投票(通过/打回/弃权)，过半数定论 |
| **收敛修复** | 问题回到执行优化，多轮直到达标 |
| **验收打回** | 你不满意→附意见打回→重做(≤3轮)→仍不行升议院/求助你 |
| **升降联动** | 大型/重要任务自动建议"议院评审?"；用户可随时手动升 |

### 1.2 支撑功能
- AI 浏览器（自动浮层右侧栏，可滑、可收）
- 半自动=人控 / 全自动=自治 的授权策略（超时自动放行 + 危险操作强确认）
- 历史任务回看 + 一键重跑
- 任务/进度/产出持久化（重启不丢）

## 2. 机制设计（状态机）

```
               ┌─────────────────────────────────────────────┐
   发起(选档)  │  强度档位：半自动(你主导) / 全自动(AI自治)      │
      │       │  可升级：重要/大型任务 → 系统建议"升议院"        │
      ▼       └─────────────────────────────────────────────┘
   执行 ──→ 质检 ──→ (达到强度) 议院评审 ──→ 优化 ──→ 收敛
      │        │            │               │
      │        ▼            ▼               ▼
      │    不满意→打回→重做  给可执行建议     可量化进步(分数↑)
      │     (≤3轮)         驱动 AI 优化       停滞即停
      ▼
   交付 → 验收(你签字) → 结束/推倒重来
```

### 2.1 卡住处理（A）
- 每阶段独立计时（默认 90s 无产出 → 熔断）
- **卡因可诊断**：API 欠费/连不上/模型纠结循环（复用 classifyApiError 认 401/402/429/超时）
- 保底交付：把已产出交付 + 明示"卡在 X 阶段，建议(换模型/补提示/继续)"
- 单 AI 卡死不阻塞整任务（容错：跳/熔断/降议院/保半成品）

### 2.2 不满意处理（B）
- 你验收不满意 → 打回附意见 → 路由"修复阶段"重做 → 再交付 → 再验收
- ≤3 轮；仍不行 → 升议院 或 明示"需要你更多指引"
- **你的意见 = 新一轮增强反馈**（对齐"你指我改"）

### 2.3 联动（C，核心亮点）
- 半自动/全自动 = 同一引擎不同强度，非两套
- 触发：① 用户主动 ② 系统检测大型/重要/犹豫 → **智能建议"议院评审?"**
- 议院 = "给可执行建议 → 驱动 AI 优化" → **评审→优化→再评审** 闭环

### 2.4 自治上限（D）
- 每轮收敛 ≤2（议院评审→优化→再评审）
- 优化须可量化进步（分数/问题数下降），停滞即停（精益收敛）
- 完成仍留"质检报告+议院建议"；用户有"一键推倒重来"

## 3. 底层逻辑（状态机实现）

```ts
type TaskState =
  | 'init' | 'executing' | 'reviewing' | 'senate' | 'optimizing'
  | 'delivering' | 'accepted' | 'failed'

interface Stage {
  name: string
  actor: ProviderModel   // 品牌模型：DeepSeek/Kimi/GPT…
  timeoutMs: number
  result?: any
  error?: { type: 'billing'|'auth'|'rate_limit'|'timeout'|'loop'; detail: string }
}

interface CollabTask {
  id: string; sessionId: string
  goal: string
  mode: 'semi' | 'senate'
  state: TaskState
  stages: Stage[]
  delivery: string
  quality?: QualityReport
  senate?: SenateReport
  round: number               // 收敛轮次
  history: PushState[]         // 可回看/重跑
}
```

**推进器**（`collab-engine`）：
```
每一步 = runStage(state) → sleep/timeout → 检查结果 → 状态迁移 → 下一 stage
卡住 → 按 error.type 分流处理（熔断/降级/保底）
```

## 5. 画面展示

### 5.1 整体布局
```
左侧边栏
  ├ 超级任务(紫 super 图标) 置顶分类组
  │   每个条目:# logo 名称 + "超级"气泡
  ├ 临时任务 / 文件夹分组
  └ 底部设置/主题
中间 协作对话流
  ├ 每消息: 品牌 LOGO 头像 + 名字 + 气泡色（执行/质检/议院按阶段出现）
  └ 底部发布框 + @执行/@议院 + 授权状态
右侧 可收缩 DetailPanel（AI 浏览器自动浮层）
  ├ AI 浏览器 tab：实时画面 + 控制台日志
  ├ 产物/文件/变更/预览/时间线
```

### 5.2 关键交互
- **AI 浏览器自动浮层**：AI 操作网页 → 自动展开右侧栏切 browser tab；停止 → 自动收起(可配)
- **顶栏右侧栏 SVG 开关**：非文字按钮，可手控收放
- **LOGO 头像**：全自动议院 = 各品牌 LOGO（DeepSeek 鲸/月亮 Kimi/花环 GPT…）
- **升降建议气泡**：大型任务完成 → 浮出"这是重要任务，建议议院评审? [评审/跳过]"
