# SuperCrzy Bot 正式发布：把 AI Agent 装进你自己的电脑

先说结论

SuperCrzy Bot 是一个完全跑在你自己电脑上的 AI Agent。

它跑在你自己的电脑上，数据存在本地一个 SQLite 文件里。模型 key 你自己填，费用你自己付，换模型是下拉框里换个名字。

它和云端 AI 助手最大的区别在于两件事：它会记住自己做过什么，以及它能真正操作这台电脑——开浏览器、点按钮、跑命令、甚至驱动那些根本没有 API 的本地软件。

MIT 开源，免费，代码在 GitHub 上。

## 一、为什么又做了一个 Agent

市面上的 AI Agent 已经很多了，不缺我们这一个。

但我们用了两个月下来，有几个坎一直过不去：

第一个坎，它不记事。 每次开新对话，你都得把项目背景、团队约定、上次那个 bug 怎么修的，重新讲一遍。它学过的经验，第二天就归零。

第二个坎，它动不了手。 大部分 Agent 停在 API 边界。你贴给它代码它能改，但它打不开你电脑上那个文件；你给它网址它能总结，但它点不了那个登录按钮。活儿真正需要完成的最后一公里，还是留给你自己。

第三个坎，它到底是黑盒。 你说的话、你的文件、你的项目结构，都存在别人的系统里。模型换了、额度用完了、服务下线了，你毫无办法。

SuperCrzy Bot 就是针对这三条做的。

## 二、核心能力：三层动手

这是最直观的差别。同一个 Agent，三种操作粒度：

第一层 · 浏览器

它跑一个真实的 Chromium，能导航、能看页面上哪些元素可点、能点、能填、能按键、能滚动。

关键是：它读页面渲染之后的内容，不是 HTML 源码。

这个区别决定了它能不能干活。源码里写的是「该商品暂时缺货」，而用户看到的按钮是「加入购物车」——这两者完全可能同时存在。

第二层 · 整个操作系统

不只是浏览器标签页，是整个桌面：截图、按坐标点击、打字、按快捷键、打开任意应用。

这一层我们做得刻意保守：默认每次调用都问你一次。

原因很实际——坐标点错窗口是不可撤销的。一次点错可能关掉你正在编辑的文档。所以设计上宁可慢半拍，也不让它自己乱来。

第三层 · 终端

最朴素，也最该被优先使用。

很多 Agent 为了读一个静态网页会去开完整浏览器，慢、贵、还容易出错。SuperCrzy Bot 会先判断：这事儿能不能用 curl？能就用 curl。

这个判断有数据支撑。我们统计了真实使用中的 3,004 次工具调用：

终端 45.7% ｜ 网页搜索 15.5% ｜ 网页抓取 13.4% ｜ 读写文件 9.8% ｜ 浏览器 3.9% ｜ 系统操作 2.0%

浏览器和系统操作加起来只有 5.9%，因为大多数任务确实不需要它们。

知道什么时候不动手，比会动手更难。

## 三、它会给自己写复盘

这是 SuperCrzy Bot 最核心的设计。

每次任务完成，它会写一份复盘存进 Playbook：这次用了什么方法、调了哪些工具、哪里失败了。

这些笔记不是给人看的汇报，是给它下次用的。 下次遇到形状类似的任务，匹配上的复盘会在开跑前注入上下文。

下面是一条真实记录。一次页面核验任务后，它自己写：

「直接打开目标 URL，用浏览器核对关键文案、截图和链接；若 browser 多次无果或超时，及时改用 web_fetch/curl 兜底，避免反复轮询同一页面。」

又一次页面摘要任务后，它是这么写的：

「先直接用浏览器打开目标页，读取可见正文即可完成摘要；本次多走了 tool_search 与 web_fetch 两步弯路。下次若页面需渲染，直接上 browser，静态内容才用 fetch，减少轮次。」

「本次多走了两步弯路」——这句话是它对自己失误的总结，不是我们写的提示词。

所以：第一次用它干某件事，和第十次用它干同一件事，是两个不同的它。

另外还有一层长期记忆：从对话中抽取的事实，随时间去重，注入时按权重加权。两者合起来构成两个学习面——可复用的过程，和关于你项目的持久事实。

最关键的是：这些都是数据库里的行。 你能打开、能查、能改、能删。一个会积累的助手，必须同时是个能被审计的助手。

## 四、评审交给另一个模型

Agent 做完一件事，怎么判断做得好不好？

大多数做法是让同一个模型自查。我们认为这没什么价值——它刚说完「我做完了」，再问「你做对了吗」，答案必然是「对」。

所以做了协作模式，任务走四个阶段：计划 → 执行 → 评审 → 交付。评审阶段换一个模型。

默认 DeepSeek 执行、Kimi 评审，还有「参议院」档位把 DeepSeek、Kimi、GPT 拉进来共同评审。

更关键的是：评审 Agent 会真的翻文件。 它去 grep、去读、去列目录，不是把代码当一段文本读完就发表意见。

经验是：能不能读文件，比模型多大重要得多。

## 五、轻到什么程度

SuperCrzy Bot 跑在三个地方：

桌面端 —— macOS（Apple Silicon）和 Windows（x64），安装包直接装。

网页端 —— 本地起一个进程，一个端口同时提供界面和 API。

以及一台 2015 年的安卓平板。

最后这个不是演示。我们在一台 2.86 GB 内存的老平板上跑起了完整的 Agent，包括浏览器工具。做法是 Android chroot + Alpine + Node 的 musl 构建 + 一个自研的 SQLite 兼容层。

讲这个是想说明一件事：这东西足够轻，能装进任何你想装的地方。

## 六、模型自己选，费用自己付

SuperCrzy Bot 不插在你和模型厂商之间。

DeepSeek、OpenAI、Anthropic、Gemini、xAI、Mistral、千问、NVIDIA NIM、智谱、Kimi、OpenRouter，或者你本地跑的 Ollama —— 填自己的 key，直连那家。

OpenRouter 一把 key 后面就是 200 多个模型。换模型是下拉框里换个名字，不是一次迁移。

所有东西都在一个文件里：`~/.supercrzy/data/supercrzy.db`

一个 SQLite 文件。能复制、能备份、能拷到别的机器上。

## 七、安全：三层防线加一道构建期校验

Agent 能跑终端命令，这很方便，也很危险。所以防线是叠起来的：

第一层 · 命令黑名单
拦掉极端情况：删根目录、sudo、fork 炸弹、curl 管道接 shell。

第二层 · 纯 Node 路径扫描
不看命令文本，看命令里的路径有没有越界。不依赖外部工具，任何环境都成立。

第三层 · 内核级沙箱（仅 macOS）
调用系统 `sandbox-exec`（对应 Linux 的 Landlock）：放行项目仓库和 `/tmp`，拒绝用户主目录下的读写。

还有一个我们认为很关键的设计：命令按段拆开判断，不按整条字符串。

因为 `rm -rf /tmp/a && echo hi > /tmp/b` 是两件事。前一件安全、后一件也安全，但 `rm -rf /tmp/a && sudo rm -rf /` 就不能只看前半截。

`rm` 按形状分级：递归删、带 sudo 删、越界删一律拦下；在 `/tmp` 或工作区内非递归删一个文件，放行。

最后一道：危险工具的声明和实际清单之间有构建期检查守着。 有人想悄悄改一行关掉某个守卫，构建直接挂掉，发不出去。

## 八、它现在还不是什么

这部分必须讲清楚：

多端同步还在做。 目前数据只在那台机器上，想在两台设备上看同一段对话还做不到。账号体系正在开发，这是下一步。

八个消息通道里有五个是国内平台（微信、企业微信、钉钉、飞书、QQ），海外三个是 Telegram、Discord、Slack。

网关没有经过独立安全审计。

构建未签名。 macOS 首次打开需要右键 → 打开，Windows 会弹一次 SmartScreen。

## 九、下载与安装

macOS（Apple Silicon）
下载 dmg → 打开 → 拖进「应用程序」。首次启动右键 → 打开。然后在「设置 → 模型」填入自己的 API key。

Windows（x64）
下载安装包，双击运行。SmartScreen 会拦一次，选「仍要运行」。

从源码构建
需要 Node 22.x 与 pnpm 10.x（版本刻意钉死，工具链不匹配是最常见的失败原因）。克隆仓库后 `pnpm install`，再 `pnpm --filter @supercrzy/server start`，打开它打印的地址。

没有订阅、没有客服、没有 SLA。MIT 许可，这份代码是你的。

项目地址：github.com/SuperCrzy/Supercrzy-Bot

## 最后

一个每次从零开始的助手，和一个记得你上周教过它什么的助手，是两个不同的产品。

前一个是很聪明的搜索引擎。后一个，你会慢慢开始真的依赖它。

至于它到底记住了什么——你能打开数据库自己看。

如果一个东西要用你的文件系统权限，它至少该让你看清楚它在想什么。
