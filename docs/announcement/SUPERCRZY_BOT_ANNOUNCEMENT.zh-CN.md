# SuperCrzy Bot 正式发布：一个跑在你自己机器上、记得自己学过什么、还能操作这台电脑的 AI Agent

**单进程的完整 Agent 工作台 —— 47 个工具、8 个消息通道、三层命令沙箱，外加一本把每次任务都变成下次上下文的 Playbook。MIT 开源、自托管、模型 key 归你自己。**

SuperCrzy 今日发布 SuperCrzy Bot —— 一套完全运行在用户自己电脑上的 AI Agent 平台。与托管型助手不同，SuperCrzy Bot 把界面、API、记忆和数据全部放在用户自己掌控的地方：磁盘上的一个 SQLite 文件。

47 个已注册工具，让这个 Agent 不停在 API 的边界。它能驱动真实浏览器、操作完全没有 API 的原生应用、执行 shell 命令，而权限模型按每次调用的**形状**判断，不按工具名一刀切。

> 「每一个 Agent 平台本质上都是关于『活儿发生在哪』的一次下注，」SuperCrzy 项目组表示。「托管型 Agent 把活儿放在别人的登录后面，标签页一关就什么都不剩。我们做的是相反的那件事：Agent、历史、模型选择都留在真正干活的人手里 —— 而因为历史是一个 SQLite 文件，他能确切地检查它以为自己知道什么。」

## 它操作电脑，而不只是调 API

大多数 Agent 到 API 的边界就停下了。它能读你粘贴的文档，但打不开那个文件；能总结一个网址，但点不了登录按钮；能描述一张截图，但截不了图。任务真正完成的最后一公里，留给了提问的人。

SuperCrzy Bot 跨过这条线，分三级递进：

**`browser`** —— 一个它自己驱动的真实 Chromium。`navigate` 打开页面，`look` 返回可点元素清单加上渲染后的文本，然后 `click`、`type`、`press`、`back`、`scroll` 逐个原语推进。它读的是页面**渲染出来**的内容，不是 HTML **声称**的内容 —— 这正是「页面说它还有货」和「按钮上写着加入购物车」的区别。

**`computer_use`** —— 整个操作系统，不只是一个浏览器标签页。`screenshot`、`click x,y`、`type`、`key combo`、`scroll`、`move`、`open <应用名>`。它能驱动一个完全没有 API 的原生程序：老旧的桌面工具、系统弹窗、要点三次才能进去的偏好设置。这个工具只在 full 权限下可用，且每次调用前都会询问。

**`shell`** —— 最诚实的那条退路。当用 `curl` 加个解析器比开浏览器更合适时，Agent 应该说一声然后换过去。在 **3,004 次**真实工具调用记录里，分布是 shell 45.7%、web 搜索 15.5%、web 抓取 13.4%、文件读取 5.1%、文件写入 4.7%、browser 3.9%、computer_use 2.0%。这个形状是对的：一个为了读静态文章就去开完整浏览器的 Agent，是在白烧用户的钱。

## 它记得什么方法奏效

大多数 Agent 会话从零起跑。SuperCrzy Bot 在每次任务完成后写一份复盘 —— 哪种方法奏效、用了哪些工具、哪里失败了 —— 存进 **Playbook**。之后再遇到形状类似的任务，匹配上的条目会在开跑前被注入上下文。

它旁边还有**长期记忆**：从对话里抽取的事实，随时间做去重，注入时按权重加权。两个不同的学习面 —— 一个是「已经做过的事里可复用的过程」，一个是「关于用户项目的持久事实」。

两者都不是微调。它们都是数据库里的行，用户可以打开、查询、修改、删除。Agent 的笔记是可读的，这正是「一个会变好的助手」和「一个只是看起来像会变好」的区别。

下面是它在一个页面核验任务后，给自己写的复盘：

> 「直接打开目标 URL，用浏览器核对关键文案、截图和链接；若 browser 多次无果或超时，及时改用 web_fetch/curl 兜底，避免反复轮询同一页面。」

还有一个页面摘要任务之后：

> 「先直接用浏览器打开目标页，读取可见正文即可完成摘要；本次多走了 tool_search 与 web_fetch 两步弯路。下次若页面需渲染，直接上 browser，静态内容才用 fetch，减少轮次。」

这些话不是团队写的提示词，是 Agent 针对自己的失误产出的笔记，在下一个同类任务里被检索并注入。

## 评审跑在另一个模型上

让模型给自己的产出打分，是一个很弱的检查。**协作中心**把任务跑过一条固定的串行流水线 —— 计划、执行、评审、交付 —— 而评审阶段刻意不使用干活的那个模型。

执行默认是 DeepSeek，质量评审跑在 Kimi 上；完整的「参议院」档位把 DeepSeek、Kimi 和 GPT 拉进同一次评审。这些审计 Agent 是**会用工具的**：它们真的读文件、grep、列目录，而不是把代码当成一大段文本读完就发表意见。每个阶段都落库，所以一次运行能扛住重启，而不是从头再来。

## 哪里都能跑，包括一台 2015 年的安卓平板

Agent 不需要别人把文件通过 API 递给它。它运行在哪台机器上，就在哪台机器上操作 —— shell、文件系统、编辑器、浏览器 —— 而同一套构建可以跑成 macOS 和 Windows 的桌面应用、跑成本地端口上的 web 应用，也能跑在**一台老旧的安卓平板**上，通过 chroot 环境加一个 SQLite 兼容层。

最后一个不是演示：一台 2.86GB 内存的平板，能跑完整的 Agent，包括浏览器工具。

## 八个消息通道，一个大脑

网关通过长连接接入**微信、企业微信、钉钉、飞书、QQ、Telegram、Discord 和 Slack**，因此不需要公网回调地址、不需要域名 —— 这正是绝大多数人卡在 NAT 后面的原因。

但更重要的是它们共享什么：同一份会话存储、同一个技能库、同一份记忆，和桌面端完全一致。在 Telegram 里问一句，那个事实就在桌面界面里。不存在一个自带失忆症的「机器人模式」。

## 你的模型、你的 key、没有中间商计费

SuperCrzy Bot 从不插在用户和模型厂商之间。用 DeepSeek、OpenAI、Anthropic、Gemini、xAI、Mistral、Qwen、NVIDIA NIM、智谱、Kimi、OpenRouter 或本地 Ollama 的 key，直接调那家。单是 OpenRouter，一个 key 后面就有 200 多个模型。

因为没有推理合约，换模型是一个下拉框，不是一次迁移。会话、消息和抽取出的记忆都在 `~/.supercrzy/data/supercrzy.db` —— 一个文件，可以复制、可以备份、可以搬到另一台机器。

## 精度来自解析

shell 执行是一个 Agent 平台建立或丧失信任的地方。防线是叠起来的，不是单层的：

- **命令黑名单**兜住极端情况 —— 删根目录、sudo、fork 炸弹、curl 管道接 shell。
- 第二层用**纯 Node 扫描危险路径**，所以在任何环境里都成立。
- 在 macOS 上，第三层是**内核级 `sandbox-exec` 策略** —— 对应 Linux Landlock 的 SBPL —— 放行项目仓库和 `/tmp`，拒绝用户主目录下的读写。

命令会按段拆分，引号和 heredoc 都考虑在内；`rm` 按形状分级：递归的、带 sudo 的、越界的命令一律拦下，而在 `/tmp` 或工作区里的一次非递归删除是放行的。

同一份克制也塑造了审批路径。敏感工具在工具定义本身上声明 `requiresApproval`，而**构建期校验器断言这个声明和危险工具清单不可能漂移**。检查跑在持续集成里，所以一行「悄悄关掉守卫」的改动会让构建挂掉，而不是发出去。

## 可用性

SuperCrzy Bot 现已发布，MIT 许可、免费开源，可从 [supercrzy.com/bot](https://supercrzy.com/bot) 与 [github.com/SuperCrzy/Supercrzy-Bot](https://github.com/SuperCrzy/Supercrzy-Bot) 获取。

**macOS（Apple Silicon）** —— 下载 dmg，打开，把应用拖进「应用程序」。构建未签名，首次启动需要右键 → 打开。

**Windows（x64）** —— 运行安装包。SmartScreen 会拦一次，因为安装包未签名。

**从源码构建** —— 需要 Node 22.x 与 pnpm 10.x，两个版本都是刻意钉死的。克隆仓库、`pnpm install`、`pnpm --filter @supercrzy/server start`，打开它打印的地址。

没有托管服务、没有订阅、没有支持合同。用户自备模型 key；要用国内消息通道，还需要那个平台的账号。数据留在产生它的那台机器上，多端同步正在开发中。
