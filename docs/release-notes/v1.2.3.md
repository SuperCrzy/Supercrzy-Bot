## Highlights

**Messaging channels reply again.** Every one of the six IM integrations — Telegram, Discord, Slack,
DingTalk, Feishu, WeCom — answered "No response" while the agent had actually done the work. All six
carried a private copy of the same code looking for a `type: "block"` payload, but the agent endpoint
emits *named* SSE events (`content_chunk`), so nothing ever matched. The same loop also parsed the
trailing partial line before discarding it, mangling any JSON split across two network chunks. Both
are now handled by one shared, properly incremental parser: partial frames are buffered, narration is
kept out of the answer, and a real failure is reported instead of being swallowed. Net effect: 168
lines of duplicated code removed, and the six channels finally deliver what the agent produced.

**Voices now match the language being read.** Three compounding problems made speech sound wrong.
The client seeded its voice setting with an English voice and sent it on every request, so the server's
"pick a voice for this language" rule could never run. Even once it could, Japanese prose is roughly 45%
kanji, so it was classified as Chinese and read by a Chinese voice. And the upstream service changed its
handshake twice in twelve days, the second time failing silently with HTTP 200 and no upgrade. Measured
on one Chinese sentence: English voice 9.77 s / ZCR 0.189 versus Chinese voice 8.66 s / ZCR 0.136 at
identical loudness — not quieter, *mispronounced*. Voices are now chosen by detected language, with kana
and hangul tested before kanji so Japanese is no longer mistaken for Chinese.

**Speech works offline-ish in mainland China.** The relay that accelerates the upstream handshake existed
and was healthy (0.875 s versus 1.5–30 s direct), but the manifest saying "here is the relay" was served
from the same overseas host the relay forwards to — so the lookup shared the very path that made the
handshake slow. The 3-second fetch timed out, the relay list came back empty, and the relay was never
even probed. The list (259 bytes) now ships inside the package and is used whenever the fetch yields
nothing; a successful fetch still takes precedence, so the relay can be rotated without a rebuild.

**Fallback speech is audible again.** When synthesis fails, the app falls back to the system voice.
macOS advertises eight "new-generation Siri" voices that, without their downloaded voice pack, emit
exactly 1.756 seconds of audio with 41% non-silence — they never read the sentence. They were ranked
first, so every fallback produced a few disconnected syllables. They now rank last, behind voices
verified to read a full sentence, and the voice list is warmed at startup because `getVoices()` is
populated asynchronously and previously returned empty on first call.

## Engineering

- **A second instance can start.** A taken port used to surface as a stack trace and a blank window.
  The server now walks to the next free port and reports the one it actually bound.
- **Updates are incremental.** The builder wrote block maps but omitted `blockMapSize` from the update
  manifest, so the updater never requested them and every update was a full ~170 MB download.
- **Windows fallback voices get an order.** The fallback table previously listed macOS names only, so on
  Windows nothing matched and the picker fell through to the first entry — very likely Huihui, the
  concatenative Windows 7-era voice. Windows 11 neural voices now rank first, then Tracy / Yaoyao, then
  Huihui and Kangkang.
- **Release tooling is in the repository.** The publish script, the VPS download helper, and the
  English-first language gate existed only on one machine. The language gate is now wired into
  `pnpm verify`, so the policy is enforced rather than merely documented.

## Known limits

- Upstream refuses 48 kHz output, so 24 kHz is the ceiling for speech.
- Latin-script languages resolve to the multilingual English voice, because glyphs alone cannot
  distinguish French from German without a locale hint from the client.
- The fallback voice table was verified on macOS only; the Windows entries follow system generation
  order but were not measured on a real Windows box.

## Install

- **macOS (Apple Silicon)** — download the `.dmg`, drag to Applications, right-click → Open on first launch
  (the build is unsigned).
- **Windows (x64)** — run the `.exe` setup; SmartScreen will ask once (the installer is unsigned).
- **Web / self-hosted** — Settings → About → *Check for updates* → *Update source* runs `git pull` + `pnpm install`
  + frontend build for you.
