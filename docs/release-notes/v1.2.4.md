## Highlights

**Windows can finally use its tools.** A full self-test on Windows 10 / Node 24 with
full permission failed in eight places at once, and most of them were one bug each:
`spawn('npx.cmd')` returns EINVAL (Node has refused to spawn `.cmd` without a shell
since the fix for CVE-2024-27980), so `computer_use` and *every* MCP stdio server
died at startup; and the sandbox compared paths with `resolved.startsWith(a + '/')`,
which on Windows builds `C:\...\Documents/` — a backslash followed by a forward slash
that never matches. That second one did not reject *some* paths: it rejected *every*
path on Windows, at every permission level, including the project root. It is why
PowerShell could write the same file while `file_write` refused it as out of
bounds — the authorization was fine, the comparison was wrong.

**Writing a file now actually writes it.** Three separate reasons the sandbox said no:

- the path comparison above;
- `HOME` was read from `process.env.HOME`, which Windows usually does not set, so the
  entire full-access branch was skipped and full behaved like the narrowest level;
- `~/.supercrzy` — where task logs and reports are written — was not in the allow
  list, so the agent could not read back a report it had just produced.

The allow list also lacked `%TEMP%`, since Windows has no `/tmp`.

**Terminal works on Windows.** The default shell was the literal `/bin/bash` with a
hardcoded `-i`. Neither exists there. `terminal_open` even looked successful while
`terminal_read` returned `ENOENT` — the session object is registered before the child
ever runs, and a spawn failure only lands in the output buffer. The shell is now
chosen per platform (`cmd.exe` via `%ComSpec%`, `/Q`), and Unix behaviour is
deliberately unchanged.

## Engineering

- **MCP servers start on Windows.** `mcp-manager` carried the same two defects as
  `computer_use`, written independently: the `.cmd` spawn, plus a second process
  spawned only for stderr whose exit handler deleted the healthy connection. Both
  callers now share one platform rule.
- **Headless-browser fallback reaches Windows.** `web_fetch`'s candidate list held
  only `/Applications` and `/usr/bin` paths, so JS-rendered pages always reported
  "no browser available". Windows install locations are now included.
- **Duplicate memories are stopped on write.** `upsertMemory` only matched keys
  exactly, so the same fact phrased differently became two rows. Lowering the merge
  threshold turned out to be the wrong lever — measurement put genuine rewrites and
  same-prefix-but-different artifacts both at exactly 0.5000, so no threshold
  separates them. Dedup now happens on entry instead: same category, threshold 0.75,
  content **appended rather than replaced**, and short keys left unjudged after a
  test caught `任务反思:A/B/C` collapsing into one row.
- **Windows gets an immersive title bar.** The native frame was hidden on macOS only,
  while the 56px traffic bar rendered whenever the app was running in Electron and
  reserved 87px on the left for the macOS traffic lights. On Windows that band was
  empty and pushed the sidebar down a full title-bar height. Window controls are now
  drawn into the same bar at the right edge, where Windows users expect them.
- **One version, not two.** The About panel showed "App v1.2.3 / Engine v0.4.0". The
  second number was a constant whose own comment required it to track `package.json`,
  with nothing enforcing it — it had been stale since October 16. Removed; the
  version now comes from the package metadata at build time.
- **Plans advance.** `create_plan` created a row per step, generated an id for each,
  and returned only the titles — so `task_update` could never be called with a valid
  id and the plan card stayed on step 1.

## Known limits

- The Windows geometry and process spawning are asserted from the code path, not
  measured on a Windows machine; the packaged build is the real test.
- `terminal_signal` with SIGINT **kills the session on Windows** rather than
  interrupting the running command, because the terminal uses pipes rather than a
  pty. Ctrl-C cannot be delivered as a character stream this way.
- Full permission still does not cover system directories (`C:\Windows`, `/etc`).
- Upstream refuses 48 kHz speech output; 24 kHz is the ceiling.
- The Windows entries in the TTS fallback voice table follow system-generation order
  but were never measured on a real Windows box.

## Install

- **macOS (Apple Silicon)** — download the `.dmg`, drag to Applications, right-click → Open on first launch
  (the build is unsigned).
- **Windows (x64)** — run the `.exe` setup; SmartScreen will ask once (the installer is unsigned).
- **Web / self-hosted** — Settings → About → *Check for updates* → *Update source* runs `git pull` + `pnpm install`
  + frontend build for you.

### 本次亮点

**Windows 上的工具终于能用了。** 在 Windows 10 / Node 24、完全访问权限下做全量自检，一次性挂了 8 个地方，
而它们大半是同一个错：`spawn('npx.cmd')` 返回 EINVAL（自 CVE-2024-27980 修复起，Node 拒绝在不带 shell
的情况下启动 `.cmd`），于是 `computer_use` 和**所有** MCP stdio 服务器都在启动阶段就死；
而沙箱用 `resolved.startsWith(a + '/')` 比路径，在 Windows 上拼出 `C:\...\Documents/` —— 反斜杠后面跟
正斜杠，永远匹配不到。这一条不是"某些路径被拒"，而是 **Windows 上每一个路径都被拒**，任何权限档位、
连项目根目录自己都一样。这也解释了"PowerShell 能写、`file_write` 报越权" —— 授权是好的，是比较方式错了。

**写文件现在真的能写进去。** 沙箱说"不"有三个独立原因：

- 上面那条路径比较；
- `HOME` 取自 `process.env.HOME`，Windows 上通常没这个变量 ⇒ full 档的放行代码整段被跳过，
  full 等于最窄档；
- `~/.supercrzy`（任务日志与报告都写在这里）不在放行列表里 ⇒ agent 读不回自己刚产出的报告。

放行列表里也没有 `%TEMP%` —— Windows 没有 `/tmp`。

**终端在 Windows 上可用。** 默认 shell 写死成 `/bin/bash` 且硬编码 `-i`，两样在 Windows 上都不存在。
`terminal_open` 甚至看起来是成功的 —— 会话对象在子进程真正启动前就登记了，spawn 失败只写进输出缓冲区，
于是 `terminal_read` 才报 ENOENT。现在按平台选 shell（走 `%ComSpec%` 的 `cmd.exe`，带 `/Q`），
Unix 行为**有意保持原样**。

### 工程

- **MCP 服务器在 Windows 上能起来了**：`mcp-manager` 带着和 `computer_use` 完全相同的两个缺陷（各自
  独立写的）—— `.cmd` 启动问题，以及额外 spawn 一个只收 stderr 的进程、它退出时把正常连接一起删掉。
  两处现在共用同一套平台规则。
- **无头浏览器兜底覆盖 Windows**：`web_fetch` 的候选列表只有 `/Applications` 与 `/usr/bin` 路径，
  需要 JS 渲染的页面一律报"无可用浏览器"。已补 Windows 安装位置。
- **重复记忆在写入时就拦下**：`upsertMemory` 原本只做精确 key 匹配，同一件事换个说法就是两条。
  试过降阈值，但实测把"真正的改写"和"同前缀不同产物"一起放在了 0.5000，阈值分不开 ⇒ 改为写入侧去重：
  同分类、阈值 0.75、**内容追加而非覆盖**、词元少于 4 个不判定（测试抓到 `任务反思:A/B/C` 被合成一条）。
- **Windows 也有了沉浸式标题栏**：原生标题栏只在 macOS 上隐藏，而 56px 横栏只要在 Electron 里就渲染、
  且左侧固定留 87px 给 macOS 红绿灯。Windows 上这条横栏是空的，还把侧边栏整整下推一个标题栏的高度。
  现在窗口控制按钮画进同一条横栏的右端（Windows 用户习惯的位置）。
- **版本号统一**：「关于」页曾显示「应用 v1.2.3 / 引擎 v0.4.0」。第二个数字是常量，注释要求它与
  `package.json` 同步但没人检查，自 10 月 16 日起就停在那儿了。已删除，版本改为构建时从包元数据注入。
- **计划能推进了**：`create_plan` 给每一步建了行、生成了 id，却只返回标题 —— 于是 `task_update`
  永远拿不到合法 id，计划卡片卡在第一步。

### 已知限制

- Windows 的几何布局与进程启动只做了代码路径断言，**未在 Windows 实机测量**；打包产物才是真正的验收。
- `terminal_signal` 传 SIGINT 在 **Windows 上会杀掉整个会话**，而不是中断当前命令 —— 终端用的是 pipe
  而非 pty，Ctrl-C 无法以字符流传递。
- 完全访问仍不含系统目录（`C:\Windows`、`/etc`）。
- 上游拒绝 48 kHz 语音输出，24 kHz 是顶格。
- TTS 兜底音色表里的 Windows 项按系统版本排序，但**未在真实 Windows 上测量**过。
