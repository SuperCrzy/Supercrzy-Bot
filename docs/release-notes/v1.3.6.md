# v1.3.6

## Security

- **The diagnostic bundle no longer contains log contents or free-text settings.**
  It was exporting up to 120,000 characters of the newest log together with every
  settings value and the local data directory. A diagnostic bundle gets pasted into
  issues and chats, and a log can carry conversation text, paths and error strings
  that masking API keys does nothing about. It now reports configuration state,
  table counts and log metadata only.

- **Uploaded HTML and SVG are no longer served as same-origin executable content.**
  The preview endpoint returned them inline with a content type derived from the
  extension, so an uploaded `.svg` with a script tag ran on the app's origin. Only
  passive formats preview inline now; everything else downloads, and every response
  carries `nosniff` and a sandboxing CSP.

## Fixes

- **File rollback no longer overwrites work you did after the task finished.** It
  compares the file against the snapshot first and skips, reporting per file, when
  they differ. A path that became a symlink is skipped rather than followed.

- **The AI browser no longer blocks clicks.** It is a native view drawn above the
  page and was consuming pointer events inside its rectangle, so clicking Settings
  could do nothing at all. It is hidden when the panel collapses and before a click
  is delivered to the app.

- **The AI browser no longer covers the changelog.** Opening a full-page screen with
  the browser open left it drawn on top.

- **Search results are ordered by date.** The comparator only checked whether a date
  existed, so results kept provider order while the description claimed otherwise.

- **Time-filtered searches no longer come back empty.** Search engines return dates
  in a localized form the parser could not read, and every result was treated as out
  of range. Results that cannot be dated are now kept and sorted last instead of
  dropped, so a query is not silently answered with nothing.

- **A plan no longer reports every step complete just because the run ended.** An
  interrupted run used to show all steps done.

- **A tool that reports `failed` is no longer rendered as done.**

- **A session only appears once the server has it.** A failed create used to add a
  local session that the server did not have, and the next message save failed
  against it. A retry after an uncertain response reuses the same id rather than
  leaving a duplicate.

- **Uploads and OCR results stay with the session that started them.** Switching
  sessions mid-upload filed the attachment under the wrong draft; a draft is no
  longer cleared when its message failed to save.

- **Attachment limits explain themselves.** Over 20MB or more than 5 files returns a
  specific message in both languages instead of a generic rejection.

- **A hanging DNS lookup no longer stalls a fetch**, and response length is clamped
  to 100,000 characters.

## Persistent goals

A session can now hold one long-running goal with its own objective, acceptance
criteria, accumulated running time and status, shown in a bar above the input.

Goals start paused. Nothing resumes automatically: an interrupted run asks whether
you have reviewed its progress before continuing, because re-running tools whose side
effects are unknown is how duplicate actions happen. Pausing moves through
"pausing" and only becomes "paused" once the run confirms it stopped.

**Not yet verified end to end with a real multi-turn task** — the execution path is
wired and covered by tests, but it has not been driven against a live model in the
packaged app.

## Engineering

- Two search post-processors had drifted apart; one was dead code that its own tests
  imported. Removed, tests repointed at the live implementation.
- Goal runs record the owning process, and runs whose process is provably gone are
  marked interrupted at boot. A live or unknown process is left alone.
