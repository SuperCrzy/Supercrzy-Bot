## Highlights

SUPERCRZY BOT now starts with a sign-in. The first launch opens a login screen, one button sends
you to the browser, and the browser hands you back a six-digit code by email — no password to
remember, no second app to install. Once you are in, the app stays in for thirty days; the window
you left open picks up the new session on its own, no restart needed.

Screen text extraction now works out of the box. macOS goes through the system Vision framework,
Windows through the system OCR engine, and when neither returns anything the app falls back to a
vision-capable model instead of handing you a screenshot with no text and no explanation.

For people who maintain a self-hosted copy, shipping a release is one command: it collects the
pending commits, drafts the three documents, runs the gates, tags, waits for CI, and publishes the
update feed and the download page.

## Features

- **Sign-in is now required, and it happens in your browser.** The app never sees your email code:
  it opens your default browser, the browser proves the login to `auth.supercrzy.com`, and a
  single-use code comes back to a local port on your own machine. The session is encrypted on disk
  and refreshed silently, so staying signed in costs you nothing until you sign out or go thirty
  days without using the app. (0999348)
- **Local OCR, with a vision-model fallback.** Reading text off a screen no longer depends on
  whatever Python packages happen to be installed. macOS uses the Vision framework (~88KB helper,
  no runtime dependencies), Windows uses the built-in OCR engine, and a vision model answers when
  the local engine finds nothing — so the feature degrades instead of failing silently. (87eaf7d)
- **One command from "we should ship" to published.** `pnpm release prepare` drafts release notes,
  the changelog and the in-app "what's new" panel from the commit log; `pnpm release ship` runs the
  gates, tags, waits for both build targets and publishes. Fewer hand-written steps means fewer
  releases where the update feed and the download page disagree. (32c1c89)

## Engineering

- **Comments in three new files follow the English-first policy.** No behaviour change; it keeps the
  baseline list shrinking, which is the only thing that stops it from growing back. (7538af7)
- **The update panel no longer shows a commit hash.** The row changed on every commit and told you
  nothing you could act on; the panel now always shows the app version and hides the source block
  when there is no git work tree. (e4bab57)
- **Ad-hoc output artifacts are ignored.** Keeps generated media and documents out of the repository
  without deleting them from the working copy. (2b3caf0)

## Known limits

- **The sign-in flow has not been completed by a human on a packaged build yet.** The auth service
  in production was verified at the protocol level (PKCE challenge and verifier, single-use code,
  replay and forged-state rejection, no change to the browser-based flow the website already uses),
  and the packaged app was verified to produce a correct login URL and to stop at the login screen.
  The last step — typing a real code from a real mailbox — is what this release asks you to do.
- **Accounts created from the app have no end-to-end encryption envelope yet.** The envelope is set
  up on first sign-in at `supercrzy.com/account`, so a user whose only sign-in was inside the app
  will be asked to set it up the first time they sign in on the website. Cross-device sync needs it;
  using the app does not.
- **No GitHub or Google sign-in yet.** Email codes only for now.
- **The builds are unsigned.** macOS needs right-click → Open on first launch, Windows shows one
  SmartScreen prompt.
- **The Windows build is produced by CI but was not run on a real machine this round.** Only the
  macOS arm64 build was installed and exercised here.

## Install

- **macOS (Apple Silicon)** — download the `.dmg`, drag to Applications, right-click → Open on first launch
  (the build is unsigned).
- **Windows (x64)** — run the `.exe` setup; SmartScreen will ask once (the installer is unsigned).
- **Web / self-hosted** — Settings → About → *Check for updates* → *Update source* runs `git pull` + `pnpm install`
  + frontend build for you.
