## Highlights

This release brings the account system and multi-device remote tasks to the desktop app, alongside a mobile-first interface refresh, the Android app's on-device runtime, and a broad security pass across the local server.

**Your conversations, encrypted and synced.** Sign in with an email one-time code and upload sessions as end-to-end encrypted backups: the passphrase never leaves your device, and the server stores only ciphertext it cannot read. Sessions, messages, tool timelines and delivery summaries all restore on a new device, with version checks so a stale upload can never overwrite newer data.

**Tell your computer to do something — from anywhere.** Devices registered to the same account appear in a picker with live online state. Submit a task from a phone or another computer and the target machine executes it; results and cancellations flow back through the same encrypted channel. Delivery status is reported honestly: a socket write is never presented as "executed".

**A security pass over the local server.** The service now binds to loopback by default and rejects remote requests without a token; the terminal connection uses single-use 30-second tickets tied to your account; file paths resolve real symlinks before use; API keys and tokens are returned masked only, and request bodies are no longer logged.

**Mobile interface and the Android app.** A new space dock, embedded site pages and immersive settings reshape the mobile layout. The Android app now boots its own on-device runtime (pruned from 258 MB to 50 MB), ships a WebView AI browser, and self-updates.

## Features

- **Account system with end-to-end encrypted sync** — email one-time sign-in, device-bound tokens, encrypted session backup with version checks and conflict protection. (459ead6)
- **Remote tasks across your devices** — register machines to one account, submit work to any online device, honest delivery states, cancellation that reaches the running task. (459ead6, 47d599b)
- **Mobile interface refresh** — space dock, embedded site pages, immersive settings and an about page. (7735af5)
- **Android app** — on-device runtime via proot (payload pruned 258 MB → 50 MB), WebView shell, phone control and the AI browser, in-app self-update. (7f851b2, 6a70e7e, 24fc05d, 6c641bb, 3da00c0)
- **AI browser improvements** — the phone side panel no longer screenshots Chrome to mirror it; a clear error replaces a 500 when the browser is unavailable. (daac898, 664a706)

## Fixes

- **TTS over IPv4 in mainland China** — direct connections pin to IPv4; the IPv6 path is reset there. (130964a)
- **Security hardening** — tool-confirm ownership resolved server-side, SSRF guard on web fetching, terminal tickets, masked secrets, request-body logging removed. (c4184f1, 459ead6)
- **Sign-in resilience** — an unreachable account service no longer forces a sign-out; logout cannot be undone by a stale poll. (d5fff4e, 47d599b)
- **Layout fixes** — the maximised panel starts at the sidebar edge and restores its width on conversation switch. (3eb994e, 310c35f)
- **Android stability** — crash recording on device, hardened foreground service, Kotlin fixes in the device bridge and tar reader. (3da6a6e, e23abdf, f744c38, f4f9654)
- **CI repaired** — the unit-test gate is green again (test timeout and timing assumptions fixed on slow runners), and the Android workflow pins JDK 17. (b2aab51, f77a5bb, f2e2169, c4184f1)

## Engineering

- Test suite: 1,826 automated tests across client, server, account service and relay.
- Sync protocol: cursor-based pagination with per-page byte budgets, persistent version sequence, tombstones that survive garbage collection.
- The release pipeline (gates, tag, builds, publisher) is documented and reproducible.

## Known limits

These are deliberate, documented boundaries — not regressions:

- **Local sessions are not yet isolated per account.** Uploads include every local session on the device; the settings page says so explicitly. Account isolation is the next major piece of work.
- **Phone-side delivery of task results is not wired yet.** The desktop bridge executes tasks and records state, but the relay currently drops upstream workspace events; the phone UI that consumes results is not built.
- **Sync is manual** (upload / download), not automatic bidirectional sync; conflict resolution has no UI yet.
- **Real WeChat / QQ channel behaviour has not been verified against live services**; the hardened paths assume the documented CDN behaviour.
- **Windows builds compile but have not been tested on a real Windows machine.**
- **Artifact previews run sandboxed**: external scripts, images and styles are restricted by design, so some third-party-dependent pages may render incompletely.
- **2–3 weeks is an optimistic estimate** for beta readiness; account isolation, encrypted result delivery and on-device validation carry real uncertainty.
