## Highlights

This release makes search work again, and removes the last desktop crash that
could leave Windows users staring at a blank window.

Search was effectively broken in 1.3.2: a module-loading bug silently disabled
every engine that needs an API key, so the app fell back to a single free engine
that redirects into a loop from mainland China. The result was "no results" on
almost every query. Search now runs on two self-hosted instances — one in
mainland China for Chinese queries, one overseas for English and technical ones —
with automatic failover and no per-search billing.

## Features

- **Two self-hosted search backends** — Chinese queries are answered by the
  mainland instance (fast, Chinese sources), English and technical queries by the
  overseas instance (Google/Brave, official docs). If one is down the other takes
  over. No search API fees. (64c8a78)

## Fixes

- **Search returned nothing on almost every query** — a config-reader bug made
  four of five engines look "unconfigured" even with valid keys. Fixed; engines
  report enabled again. (cb3fbee)
- **Windows white screen after install** — the app now waits for the backend on
  the address it actually listens on, survives a failed data migration instead of
  crashing, and shows the real reason instead of a blank window when startup
  fails. (d404c77)
- **Desktop backend crashed on boot** — a 342 MB peer dependency was pruned by the
  build while still being imported, killing the backend before it could listen.
  Both helpers are now vendored; the dependency is gone. (e78e331, 251cb87)
- **AI browser reported a "loop" during normal use** — repeated identical
  snapshot/screenshot calls are how the browser works, not a stuck loop. The
  browser tool is exempt and the generic threshold was raised. (b238630)
- **Two voices at once when sending a message** — sending now stops the previous
  reply's reading immediately. (9d2a3eb)
- **Context-usage popover was invisible** — it was clipped by the top bar; it now
  floats above the page. (bade658)
- **Top bar layout on Windows** — the window title sat over the sidebar and left a
  visible gap above the logo. Windows now places the logo in that band; macOS is
  unchanged. (938d4c4, 6ba19ae, c13a2aa, 92d1014)
- **Product name** — the app is called SUPERCRZY everywhere (it was drifting
  between "Super Crazy" and "SUPERCRZY BOT"). (337c5d3)

## Engineering

- Vendored two helper functions from the WeChat SDK, removing a 342 MB
  dependency and the whole class of "pruned but still imported" startup crashes.
  (251cb87)
- CI: replaced a retired macOS runner, added a Docker mirror override with
  retries, and fixed the Windows packaging gate that was reading the wrong
  directory. (190b76b, 3ed1e79, 4f18588, 9cfb308, f18236f)

## Known limits

- **Windows verified by code and by reproducing each failure locally, not on a
  physical Windows machine.** The white-screen fixes address every link in the
  chain that was measured, but the packaged build has not been re-tested on
  Windows hardware.
- **WeChat channel may be unavailable in packaged builds.** The SDK expects Node
  >= 22.13 while the desktop runs Electron's Node 20. It now degrades quietly
  instead of breaking startup, but sending/receiving may not work.
- **The mainland search instance only returns Chinese results.** Its upstream
  engines (360/Baidu) are Chinese-indexed by nature, so English queries are routed
  overseas. This is a property of the engines, not a configuration issue.
- Serving 80/443 to the public from a mainland-China host requires ICP filing; the
  mainland instance is currently exposed on a subpath of the bare IP.
- Product name in the packaged binary is pinned to the old value so existing
  installs can still auto-update; unifying it needs an update-chain transition.

## Install

- **macOS (Apple Silicon)** — download the `.dmg`, drag to Applications, right-click → Open on first launch
  (the build is unsigned).
- **Windows (x64)** — run the `.exe` setup; SmartScreen will ask once (the installer is unsigned).
- **Web / self-hosted** — Settings → About → *Check for updates* → *Update source* runs `git pull` + `pnpm install`
  + frontend build for you.

### 本次亮点

这次让搜索重新可用，并彻底解决了可能导致 Windows 用户看到白屏的最后一个环节。

1.3.2 的搜索其实是坏的：一个模块加载 bug 让所有需要 API key 的引擎都被静默判为「未配置」，只能退化到那个在中国大陆会陷入重定向循环的免费引擎，所以几乎每次搜索都是「没有结果」。现在搜索跑在两个自建实例上——中国大陆的实例负责中文查询，海外的实例负责英文与技术类查询——互为备份，且不产生按次费用。

### 修复

- **搜索几乎每次都没有结果**：配置读取的 bug 让五个引擎里的四个被误判为「未配置」，即使 key 有效。已修复，引擎恢复正常。
- **Windows 安装后白屏**：应用现在在它真正监听的地址上等待后端；数据迁移失败不再崩溃；启动失败时显示具体原因而不是白屏。
- **桌面端后端启动即崩溃**：构建时删掉了一个 342MB 的 peer 依赖，但代码仍在静态引用它，后端在监听端口前就退出了。两个函数已本地化，依赖彻底移除。
- **AI 浏览器在日常使用中被误判为「死循环」**：重复的 snapshot/截图调用是浏览器的工作方式，不是卡死。浏览器工具已豁免，通用阈值也已提高。
- **发消息时两个声音重叠**：现在发消息会立即停止上一段的朗读。
- **上下文用量弹窗看不见**：它被顶部横栏裁掉了，现在浮在页面上方。
- **Windows 顶部横栏布局**：标题压在侧边栏上、LOGO 上方留空。现在 Windows 把 LOGO 放在那一栏，macOS 保持不变。
- **产品名统一为 SUPERCRZY**（之前一会儿「Super Crazy」、一会儿「SUPERCRZY BOT」）。

### 已知限制

- **Windows 部分只做了代码核实与本地复现，没有在 Windows 真机上复测。** 白屏的修复覆盖了实测到的每一个环节，但打包后的版本尚未在 Windows 硬件上验证。
- **打包版本的微信通道可能不可用**：SDK 要求 Node >= 22.13，而桌面端跑的是 Electron 的 Node 20。现在它会安静降级而不是拖垮启动，但收发消息可能不工作。
- **中国大陆的搜索实例只返回中文结果**：它的上游引擎（360/百度）本身就是中文索引，所以英文查询会路由到海外实例。这是引擎自身的性质，不是配置问题。
- 从中国大陆主机通过 80/443 对公网提供服务需要 ICP 备案；当前大陆实例挂在一个 IP 的子路径上。
- 打包二进制里的产品名暂时锁定为旧值，以保证已装用户能继续自动更新；统一名称需要更新链过渡。
