# supercrzy.com × SUPERCRZY BOT 联合方案（休息场景版）

> 日期：2026-08-21
> 场景：用户在休息/碎片时间浏览新闻时，如何自然衔接 BOT 执行层

## 一、场景约束（设计前提）

| 约束 | 影响 |
|---|---|
| 低专注、碎片时间 | 不能有复杂引导/多步表单 |
| 不想被打断 | 不能每篇文章弹窗推销 |
| 不想打字 | 动作必须零打字、一键触发 |
| 随时可能划走 | 任务可暂停、可异步执行 |

**核心原则**：动作从内容里自然长出来，而不是"看完新闻被拉去干活"。

## 二、三层联合模型

### L1 阅读延伸（所有文章常驻）
- 收藏稍后读：BOT 闲时生成摘要推送
- 追踪事件：订阅 watchlist，事件更新自动推送
- 追问一句：预填文章上下文，用户只需选问题模板
- 生成摘要：读不完的文章，一键让 BOT 提炼

### L2 任务升级（评测/工具/教程类自动出现）
- 识别可执行信号（模型对比、工具试用、教程实践）
- 按钮：去执行 / 对比这两个模型 / 帮我跑一下
- deep link 预填上下文：`supercrzy://?q=<文章上下文+动作意图>`

### L3 结果回流（闭环飞轮）
- BOT 执行笔记 → 沉淀到 Lab（真实 UGC）
- 反哺选题：用户真在关心什么 → 网站做什么内容
- 品牌叙事：网站"想明白"，BOT"做出来"，互相造血

## 三、技术落地要点

| 端 | 现状 | 要做 |
|---|---|---|
| 网站侧 | deep link 协议 0 命中 | 注入按钮 SDK + 信号识别脚本 |
| BOT 侧 | deeplink.ts 已实现 ?q/?session/?workspace | 任务卡解析 + 确认 UI |
| 回流 | 无 | 执行笔记 POST 回网站 API |

## 四、落地顺序（MVP）

1. **第一步（1-2 周）**：CRAZE escalate 按钮化 + L1 两个动作（收藏稍后读、追问一句）
2. **第二步（1 个月）**：L2 可执行信号识别（评测/工具类）
3. **第三步（2-3 个月）**：L3 执行笔记回流 + 数据反哺选题

## 五、休息场景专属设计

- **异步执行**：点击后不等待，BOT 排队执行，结果通过通知闲时推送
- **可随时停**：任务卡一键暂停/放弃，无心理负担
- **渐进暴露**：第一次只给 1-2 个选项，熟悉后再展开更多动作
- **移动优先**：休息场景多为手机，deep link 移动端原生唤起体验最佳
