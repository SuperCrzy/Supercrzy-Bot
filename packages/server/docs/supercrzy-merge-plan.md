# SUPERCRZY 认知层 × 执行层 合并落地方案

> 调研对象：supercrzy.com（认知层/媒体端） + SUPERCRZY BOT Agent（执行层）
> 调研方式：抓取 supercrzy.com 首页 / About / CRAZE / Rank 四个真实页面
> 日期：2026-06

---

## 一、现状盘点：supercrzy.com 是什么

不是"AI 新闻网站"，而是**决策层媒体**：每个页面回答一个实用问题。

| 层级 | 职能 | 现状证据 |
|---|---|---|
| News | 报道"后果"而非"公告" | 头条《OpenAI Finally Hit the Brakes...》讲安全事件影响 |
| Rank | 模型真实排行 | 带价格/tk/s/厂商/国家（如 Opus 5 $10） |
| Lab | 实测评测 | 摩擦、可靠性、日常可用性 |
| Topics | 主题聚合 | 分层阅读 |
| **CRAZE** | 理解层（内嵌 AI） | "explain the page, not become another chat product"，每次只给一条下一步 |

**核心原则**：CRAZE 管理解，Agent 管行动；报道优先级 = 后果 > 公告。

---

## 二、断点分析：认知 → 执行 缺什么

| 断点 | 现状 | 缺口 |
|---|---|---|
| 阅读完成 | CRAZE 给出"一条下一步" | 下一步**没有行动入口** |
| 用户决策 | 读者知道"该用什么/该试什么" | 无法直接触发执行 |
| 数据回流 | 网站内容单向输出 | 无 Agent 使用数据回流到内容选题 |
| 品牌协同 | 同名不同域 | 未互相导流/背书 |

---

## 三、合并落地方案（三阶段）

### 阶段 1：打通（网站 → Bot 入口）
- 网站每个页面（News/Rank/Lab）加"交给 SUPERCRZY BOT"按钮，一键唤起 Agent
- 复用 CRAZE 的"一条下一步"，把它变成 Agent 的**任务卡**（task card）：
  - 例：Rank 页 → "跑一下 Opus 5 vs GPT-5 的吞吐对比" → Agent 接单执行
- 技术：网站前端嵌入 Agent 的 Web 入口（packages/client），或 deep link

### 阶段 2：植入（Bot 吸收内容能力）
- Agent 内新增 **CRAZE 技能**：抓取 supercrzy.com 内容作为知识源
- 技能体系扩展：content-pipeline（已有）对接网站选题 → Agent 执行
- 新增"决策助手"会话模式：用户问"我今天该看什么" → CRAZE 排序 + Agent 抓取全文摘要

### 阶段 3：闭环（数据回流 + 品牌协同）
- Agent 使用数据（哪些模型被实测、哪些工具被常用）回流 → 网站 Rank/Lab 选题依据
- 网站作为 Bot 官方落地页/宣传阵地（用户记忆中的推广计划）
- 双向导流：网站读者 → Bot 用户；Bot 用户 → 网站深度内容

## 四、里程碑与验收

| 里程碑 | 交付物 | 验收标准 |
|---|---|---|
| M1 打通 | 网站出现"交给 BOT"按钮 | 点击后能唤起 Agent 并携带任务卡 |
| M2 植入 | CRAZE 技能上线 | Bot 能回答"网站今天讲了什么 + 我该做什么" |
| M3 闭环 | 回流报表 | 每周自动生成"模型实测热度榜"供内容团队使用 |

---

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 网站与 Bot 技术栈异构 | 只走标准协议：HTTPS + JSON 任务卡 + MCP |
| 内容版权/引用 | 只抓自家网站，版权无冲突 |
| CRAZE 定位漂移（变成聊天机器人） | 保持"每页一答、只给一条下一步"原则 |
| 工作量排期 | 三阶段独立可交付，每阶段可单独上线 |

---

## 六、一句话总结

**认知层负责"让人想明白"，执行层负责"让人做出来"；用任务卡打通两端，用数据回流形成生态闭环。**
